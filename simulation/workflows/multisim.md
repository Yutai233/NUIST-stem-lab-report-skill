# Multisim：XML 生成与原生仿真验收

本文件是软件级工作流。课程任务由当前材料和课程仿真实验卡决定；软件名不能代替课程识别。默认主线为 **任务规格 → XML 生成 → 原生网表核对 → 求解 → 数值验收 → SaveAs 后重开复验**。GUI 仅在用户或本次教师要求中作为交付项时进入独立分支。

按需读取：[XML 对象与连接规则](multisim-xml.md)用于生成/修改工程；[原生执行器](multisim-native-runner.md)用于单频 AC 与瞬态；[公共证据规则](../evidence-and-verification.md)用于验收和清理。只要求方案时不运行软件；只核验已有证据时不自动重跑；用户已要求完成仿真时直接执行必要的生成、求解和复验。

## 1. 确定任务与成功条件

从本次材料建立任务规格，不把旧实验的数值、位号或工况数量复制为默认值：

- 材料来源及页码；电路器件、模型、额定参数、拓扑、接地、仪器和测量方向。
- 工况及先后顺序，每步修改与保持的参数；源幅值的峰值/RMS约定及频率。
- 分析类型、初值、采样/步长、总时长与稳态窗口；这些值由电路时间尺度及所需精度决定。
- 输出量与单位、物理验收公式、容差及来源、重开复验范围；近零量使用绝对容差。
- 交付的工程、数据、图表；交互/面板/桌面截图是否为本次必做项。

先确定模型边界。固定开关工况可以证明对应电气状态；不能证明热键或连续交互。替代器件、移除初始化/动画或理想化负载会改变实验含义，必须写明适用性；教师指定模型不允许替代时，保留未完成项并寻找合法模板。

## 2. 预检与最小闭环

在任务目录记录软件构建、工程 schema/版本、COM 注册及位数、宿主、依赖版本/提交和许可可用状态。许可只记录运行结果，不收集密钥。

已实跑的参考环境为 Windows、Multisim 14.0.593.0、schema 67、x86 .NET COM 宿主；它只证明所用本机模板、单频 AC 与 TRAN 路线。其他版本/器件/分析需本次验证，不能强改版本字段使其看似匹配。

1. 使用合法本机样例或用户提供的已知正常工程，在新目录复制并记录 SHA-256。
2. 验证解码/回编码往返，再由真实 Multisim 打开，导出网表并枚举输出。
3. 跑与任务有关的小型分析，检查数据非空、有限、坐标和量级合理。
4. 原生 SaveAs 到新文件，重新 OpenFile 并复算；记录实际复现等级。

接口不可用时先核对版本、位数、注册和报错。无需为使用 COM 安装整套 MCP；可用匹配位数的宿主。不自动改系统策略或重启有用户文档的应用。

## 3. 从规格生成工程

采用“已审计模板 + 有限对象库 + 本次电路规格”，不自由拼造私有 XML 或器件库 ID。已有工程优先在副本上作必要修改；无工程时从本机合法样例提取所需对象。

任务级构建器负责课程参数、器件映射和工况；通用 Skill 只保留对象规则及执行协议。新增器件族、层次电路、多单元符号或不同 schema 时先验证其注册方式，不能直接套用旧单 sheet 修复器。

构建步骤：

1. 解码副本，核对模板来源、schema、器件及模型是否满足规格。
2. 分配新对象 ID，保留合法模型引用，同步逻辑引脚、图形、网络注册和线端归属；规则见 [XML 参考](multisim-xml.md)。
3. 修改真实参数、数值缓存与显示值；生成工况工程及输入清单，记录模型变化。不能只改标签。
4. 往返解码并检查参数、引用、连接不变量。对修改过的连接构建器加入断路/跨网误接负例，确保检查器会拒绝错误。
5. 原生打开并导出网表，逐关键引脚对比规格；确认源—负载—回流路径、地、支路、开关状态和仪表接法。

XML 通过只能进入原生验收，不能直接成为最终工程。图上重合或线条连通不能证明电气连通。

## 4. 原生执行与数值验收

先通过一个代表工况，再扩展批次；有状态的 Multisim 会话串行使用。可复用 [原生执行器](multisim-native-runner.md)，它输出运行证据，不替代课程物理验收。其支持范围是单频 AC 加 TRAN；OP/DC/扫频/数字时序按实际接口另建适配，不强套此执行器。

- `EnumOutputs(0)`枚举本工程真实输出。把输出名绑定到网络/引脚、被测量、单位与正方向；不能猜 `V(node)`，也不能凭读数“像正常值”判断探针位置。
- 分析使用新请求和独立结果目录，等待带截止时间。保存方法标识、数组维度、原始复数/采样值、软件版本和错误；不能沿用旧缓存读数。
- 当前已验证契约：单频 AC 的 `GetOutputData` 为 3×N（频率、实部、虚部），TRAN 为 2×N（时间、实值）。其他接口/版本重新验证，不能按长度猜幅相。
- 瞬态检查时间递增、实际覆盖所需窗口、采样足够；返回点数不必等于请求数。采样请求不等于求解器步长，XML 分析配置与返回时间轴分别核对。
- 验证 KCL/KVL、功率守恒、数量级和本次理论预期；RMS 电流不能按标量相加。非线性/有初始化脚本的模型分别核对 AC 与 TRAN 适用范围。
- 自适应采样按时间积分；多通道时间轴不同则先按声明方法对齐。计算 RMS、平均功率及 P/(Urms·Irms)，保留公式和窗口。非正弦功率因数不能以 cosφ 代替。
- 搜索值与理论设定值分开。搜索记录区间、停止阈值、每次参数及原始输出，再对找到的点原生复验。

出现全零时按证据定位：先看原生网表的源与回流，再看各引脚注册和线端 owner，随后核对真实参数、激励、输出请求及模型运行行为。合法零值不自动判错；本应带激励而全零也不能按“求解完成”判通过。

## 5. 保存、重开与交付

SaveAs 新路径后，把保存文件作为新一轮输入，重新枚举/求解并比较关键参数、网络及数值。锚点覆盖不同拓扑和参数边界；若任务要求逐工况重现则全部重跑。记录每个比较量、阈值和误差。

复现等级按实际动作填写：`api_reopen`（重新 OpenFile）、`document_closed_reopen`（确认文档关闭后从文件打开）、`process_restart`（确认重启后打开）。新建 COM 宿主不等于 Multisim 冷启动；不能用强杀用户应用制造更高等级。

交付工程、原始输出、派生表、运行清单和复现入口。每项状态为 PASS/FAIL/UNVERIFIED；原生执行成功、物理验收成功、重开成功分别登记。所有本次必做项通过才算整体 PASS；未要求的 GUI 不构成缺项。原生图纸导出、XML 预览、数据绘图与真实 GUI 截图分别标明来源。

## 6. 失败与恢复

| 现象 | 下一步 |
|---|---|
| COM 连接/打开失败 | 保留版本、宿主、错误；用已知工程分离环境与生成文件问题 |
| 图对但全零/断网 | 对比原生网表和引脚—网络映射，检查全部线端 owner，不能只补三岔点 |
| AC 正常而 TRAN 异常 | 检查激励、初始化/动画、静态模型表达式、步长和稳态窗口 |
| 输出为空或超时 | 保存已有数据及状态，停止当前批次；不要继续提交新请求 |
| SaveAs 后重开有差异 | 核对落盘参数和网表，以重开结果定位，保留两次证据 |
| 进程级崩溃或挂起 | 只结束自己创建的执行宿主；不批量终止 Multisim 或用户文档 |

修复需有具体依据，保留失败现场，再换新输出目录验证。相同故障修复后仍重复时停下定位，不盲目循环。COM 阻塞不能直接推断模型在 GUI 中也无法运行。

## 7. 工作目录与迁移

- `inputs/`：原始材料副本、已审计工程/模板及指纹。
- `scripts/`：任务级生成器、物理验收器和串联入口；由脚本或清单位置解析路径。
- `outputs/<run>/`：每轮生成工程、原始数据、派生结果及清单，拒绝覆盖旧证据。
- `vendor/`：必要依赖与版本、提交、许可记录；不把 NI 模板或个人材料放进公共 Skill。
- `audit/`：能力验证、路径迁移、清理清单及关键失败证据。

迁移先建立原路径→新路径→SHA-256映射，更新当前入口，旧运行清单保持历史真实性。清理必须在复现成功后按 [公共清理规则](../evidence-and-verification.md)执行，不能删除仍被入口或正式清单引用的依赖。
