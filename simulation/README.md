# 仿真辅助入口

本层处理仿真实验的搭建、执行和验收，不替代课程提示词、教师任务书或报告模板。

## 加载顺序

1. 按课程登记表确定课程，读取本次教师材料及该课程已登记的仿真实验卡。
2. 区分搭建方案（不运行）、已有结果核验（不重新执行）、实际执行（用户明确要求后运行）三种模式，并读取 [证据与验收](evidence-and-verification.md)。
3. 按本次软件读取工作流；当前已接入 [Multisim](workflows/multisim.md)。不要预先加载或宣称支持其他软件。
4. 在独立任务目录保存输入指纹、工程副本、原始输出及运行清单。只有用户要求报告时才进入报告制作流程。

## 执行边界

- 用户要求提示词或搭建方案，不代表授权启动软件、安装依赖或改配置。用户明确要求实际实验时，先验证本机版本、接口和许可可用性。
- 执行路线服从本次用户要求。Multisim 默认采用“XML/模板生成 → 原生接口求解 → 数值验收 → 保存重开复验”；只在用户或教师明确要求交互、面板或桌面截图时增加 GUI 分支。原生图纸导出不等于桌面截图。
- 原件只读，输出使用新路径。应用异常时停止当前批次，记录最后成功工况；关闭可能存在未保存文档的进程前确认，不强杀恢复。
- 软件能打开和求解不代表满足全部教师要求。按本次必做项列出完成状态、模型边界和缺项，不把未要求的 GUI 操作变成完成门槛。生成器和物理验收器按材料建立，不继承旧实验参数。
