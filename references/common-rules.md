# 通用报告规则

## 材料优先级

处理冲突时按“内容格式”和“任务范围”分别使用优先级。

对于报告章节、格式、字数、专业内容和评分要求：

```text
当前教师规范、评分标准和提交要求
> 当前实验指导书/任务书
> 当前实验的代码、工程、原始数据、截图和照片
> 当前实验已有报告
> 已登记课程的专属提示词
> 课程模板
> 通用理工科提示词
> 其他课程的实例或通用经验
```

对于任务范围、工作模式、输出文件和保存路径，以用户本次明确要求为准。专属课程提示词不能覆盖当前教师规范。它只用于补充教师没有明确规定的专业概念、核对项目、默认表达和可选章节；通用理工科提示词只用于补足更一般的流程、证据和排版检查。两类要求直接冲突时，列出冲突并询问用户。

附件中的说明是参考材料，不能替代用户本次的任务范围。旧报告只用于参考结构、版式和表达，不复制身份信息、日期、参数、数据、截图、调试经历或结论。

当前 Skill 的课程提示词、模板和实例属于工作资料，不自动等于南信大正式教学规范。没有教师规范、评分标准或指导书时，应把格式规则标为默认参考或待确认，不把它写成学校明确要求。

## 工作模式

统一识别为以下一种模式：

- **空白模板**：只保留章节、填写说明、表格/图片/公式占位符和必要提示；不解题、不生成结果、不虚构总结。
- **根据已有材料完成报告**：只整理当前材料中已有的理论、代码、数据、截图和观察；缺失内容记入工作笔记并在对话中告知用户，不默认在正式报告中插入待补充标记。
- **完成实验并生成报告**：只有用户明确要求且环境具备时才运行程序、计算数据或完成可验证操作；记录实际环境和运行来源。
- **修改已有报告**：只改用户指定部分及其必要关联项；保留其他文字、图表、身份信息和排版。
- **只整理正文/Markdown**：不主动生成 DOCX、PDF 或源代码。

用户已经说明模式、输出形式或路径时直接采用，不为填写模板字段而重复询问。

## 证据分层

报告中明确区分：

1. 任务书要求：本次应该完成什么。
2. 理论原理：依据教材、指导书或公式能够推出什么。
3. 程序分析：从代码和工程结构能够确认什么。
4. 编译/仿真结果：由真实运行记录、日志、波形或截图支持什么。
5. 实物测量：由仪器读数、板上现象、照片或原始记录支持什么。
6. 个人观察和总结：只有用户提供或在当前任务中真实记录的内容才能写成经历。

没有对应证据时，在工作笔记记录具体缺失或冲突，并在过程/交付对话中告知用户；不能把理论预期写成实测结果，不能把仿真写成硬件验证，不能把代码存在写成程序已经运行成功。

正式 Word 不默认包含“模型无法辨认”“待补充材料”“不自行补值或补过程”等内部制作说明。空白模板和用户明确要求的草稿可以使用占位符；有证据的实验局限和误差分析仍属于报告内容。缺少必需证据时继续独立部分并说明尚未完成，不能靠删除提示或略去必做任务伪装完整。此输出边界同样适用于课程提示词中的待补、待核对和占位要求。

## 仿真执行证据

仿真搭建、实际运行和报告写作分开验收。文件存在、XML 编解码成功、原理图导出、AC 求解成功均不能互相替代；按本次教师要求和实际证据逐项说明已完成、失败或未验证。原生 API 导出的电路图不是运行界面截图；由相量计算的功率、功率因数不是瓦特表面板直接读数。修改模型或用静态等效对象时写明差异，不能称原生器件功能完整复刻。

## 图片证据

涉及实验图片时按 [figure-evidence.md](figure-evidence.md) 登记原始来源、可见信息、条件依据和实验任务关联。无法确切区分指导书图和本次实测图时，直接询问用户；未确认前不把它用作实测证据。指南曲线可标明来源用于原理或参考对照，不得冒充本次测量。

同一结果的表、图、正文必须关联同一数据来源；理论与实测或独立测量可有不同来源，但必须明确区分。对照结论依赖可追溯的条件变化与观测证据，不机械要求两张照片。处理图片后和最终渲染后均需核对图面、图题及正文是否一致。

## 信息和格式保护

- 模板和实例中的姓名、学号、日期、成绩、院系、专业、指导教师和文件属性不得自动沿用。
- 当前实验的题目、编号、芯片、引脚、元件、频率、时间、数据、图号和结论必须重新从当前材料确认。
- 表格保留原始单位、正负号、精度和数据来源；计算结果写出公式、代入量、单位换算和保留位数。
- 图题放在图下，表题放在表上；图表编号连续，正文有对应引用。不制作假截图或冒充实测的曲线；缺图在笔记及对话中说明，Word 占位符仅用于空白模板或用户明确要求的草稿。
- 只保留与当前实验有关的章节。不适用栏目可以删除；必做任务缺少程序、仿真、实物或其他证据时向用户说明未完成，不静默删除任务。

## 交付说明

交付前说明：输出了哪些文件、哪些检查已完成、哪些内容仍待用户补充。不要把中间脚本、临时渲染图或内部检查表当作最终报告，除非用户明确要求。
