# 新理工科课程标准接入要求

本文件用于后续把一门新的南信大理工科课程接入 `nuist-stem-lab-report`。它是资源接入标准，不是某门课程的实验报告提示词。接入完成后，Skill 才能在识别课程时稳定选择该课程的规则、模板和实例。未登记课程可以先使用 [general-stem-lab-prompt.md](general-stem-lab-prompt.md) 作为基线，但当前教师规范始终优先。

## 一、接入目标

新增课程至少应达到以下结果：

- 能从课程名称、实验主题、仪器/软件、专业术语或用户指定目录识别该课程；
- 有一份课程级提示词，说明该课程的报告内容、专业概念、证据要求和不适用栏目；
- 有一个可复制或填充的 DOCX 模板，或明确说明该课程只交 Markdown/PDF；
- 有教师规范、实验指导书、评分标准或可靠参考材料中的至少一种作为格式依据；
- 没有实例时也能工作，但必须降低格式推断强度并标注依据不足；
- 能通过一个真实实验任务验证“选课、生成、导出、验收”链路。

无论课程是否已经登记，均使用以下覆盖关系：

```text
本次教师规范/评分标准/实验指导书
> 用户本次明确要求
> 课程专属提示词
> 通用理工科提示词
> 模板、实例和其他默认经验
```

如果教师规范与用户本次要求发生冲突，先向用户指出冲突并按用户最终确认处理；如果教师没有规定某项，才由课程专属提示词或通用理工科提示词补充。

## 二、推荐目录结构

课程目录名使用简短、稳定、易识别的中文名称，避免把学期或个人姓名写进目录名：

```text
新课程/
├── 新课程实验报告通用提示词.md
├── 新课程实验模板.docx                 可选，但有 Word 报告时建议提供
├── example/                             可选；优先放不同来源的完成版实例
│   ├── example-01.docx
│   └── example-02.docx
└── source-notes.md                      建议；记录来源、学期和可借鉴范围
```

如果课程有不同实验类型且格式差异很大，可以在课程目录内分层；只有在确实存在稳定差异时才拆分，不为单个实验建立复杂目录。

## 三、最低材料清单

接入前收集并区分以下材料：

1. **课程身份**：正式课程名、常用简称、可能出现的英文名或旧称。
2. **识别关键词**：实验主题、核心仪器、软件、器件、计算方法和专业术语。
3. **课程提示词**：课程角色、写作口径、实验结构、专业核对点、真实性边界和输出要求。
4. **教师要求**：实验报告要求、评分表、实验指导书、课程大纲或教师明确消息；注明来源和适用学期。
5. **版式资源**：基础模板、教师示例或班级统一格式；没有 DOCX 时说明实际提交格式。
6. **完成版实例**：至少一个即可开始接入，两个及以上不同来源更适合交叉比较；实例不足不能阻塞接入。
7. **验证任务**：一份可用于测试的真实实验材料，最好同时包含指导书、数据/截图和输出要求。

缺少的材料应在 `source-notes.md` 中列为“未提供”，不能用其他课程的资料补齐。

## 四、课程提示词必须回答的问题

新增课程的提示词至少应包含：

- 本课程适用范围和不适用范围；
- 当前任务的工作模式：空白模板、根据材料完成、实际运行后完成、修改已有报告或仅整理正文；
- 本课程的报告结构，但允许按当前教师要求增删；
- 本课程需要核对的公式、单位、符号、仪器、实验对象、软件、代码或图表；
- 理论、程序分析、仿真、实物测量和个人观察之间的证据边界；
- 缺少数据、图片、运行记录或个人信息时的处理：记录在工作笔记并向用户说明，正式报告不默认插入制作备注；空白模板或用户明确要求的草稿可使用占位符；
- 图片来源、条件与实验任务的对应规则；无法区分指导书图和本次实测图时询问用户，不猜定来源；
- 生成前需要询问的关键问题；
- DOCX/PDF 交付前需要检查的课程特有项目。

提示词不得把某一份实例的姓名、学号、日期、参数、数据、结论或个人经历写成默认内容，也不得把单个实例独有的章节直接规定为所有实验必需章节。

## 五、实例使用和来源记录

完成版实例只用于观察结构、版式、图表、语气和分析深度。处理实例时：

- 多个来源：只采纳与教师要求、指导书和模板共同一致的特征；
- 单个来源：作为局部样例，不据此推断课程硬性规范；
- 没有来源：以教师要求和模板为主，不跨课程借用成品报告；
- 所有实例：删除或替换旧身份、日期、数据、截图、参数、代码和结论。

建议在 `source-notes.md` 记录：

```markdown
# 资源来源说明

- 课程正式名称：
- 课程简称/别名：
- 适用学期或班级：
- 教师规范来源：
- 模板来源：
- 实例来源类别：教师示例／本人旧报告／同学报告／其他
- 实例可借鉴内容：
- 实例不可复用内容：身份信息、数据、结论、参数等
- 尚未确认的规范：
```

## 六、登记到课程映射表

在 `references/course-registry.md` 中增加一行，至少填写：

| 字段 | 要求 |
|---|---|
| 课程名 | 使用正式名称，必要时补充简称/别名 |
| 识别关键词 | 至少 3 个有区分度的词 |
| 课程提示词 | 相对于 Skill 根目录的真实路径 |
| 基础模板 | 有则填写真实路径，无则写明输出限制 |
| 完成版实例 | 路径和数量；无则明确“当前无” |
| 当前策略 | 说明实例不足、教师规范缺失或特殊格式 |

同时检查所有路径真实存在，课程提示词中的模板文件名与登记表一致。

## 七、接入验收

接入后用一个真实请求验证：

1. 能根据材料识别新课程，无法确定时会询问而不是猜测；
2. 能加载新课程提示词和模板，不误读其他课程规则；
3. 空白模板模式不会生成虚假数据、结论或实验经历；
4. 完整报告模式会区分当前材料、理论预期和实际证据；
5. 没有实例时会按降级策略工作，并说明格式依据不足；
6. 生成 DOCX/PDF 后能按 [docx-pdf-qa.md](docx-pdf-qa.md) 检查；
7. 输出文件、未完成验证和待补材料能在最终说明中分别列出。

接入失败时，优先修正课程提示词、资源映射或材料来源说明，不要通过增加跨课程的固定规则来掩盖缺失材料。
